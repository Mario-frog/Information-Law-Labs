# Лабораторна робота №5

## Тема: Дослідження протоколу автентифікації Фейге — Фіата — Шаміра (Feige-Fiat-Shamir)

### Опис

Програмна реалізація криптографічного протоколу автентифікації Фейге — Фіата — Шаміра (FFS) мовою Python.

Протокол дозволяє підтвердити знання секретного ключа без його розкриття, використовуючи принцип доказу з нульовим розголошенням (Zero-Knowledge Proof).

### Мета роботи

Дослідити принцип роботи протоколу автентифікації FFS, реалізувати генерацію ключів, процес ідентифікації користувача та перевірити стійкість протоколу до атак.

### Функціональні можливості

- Генерація відкритого та секретного ключів.
- Проведення раундів автентифікації між Prover та Verifier.
- Перевірка чесного учасника та учасника з неправильним секретним ключем.
- Моделювання атаки повторного відтворення (Replay Attack).
- Моделювання атак методом вгадування.
- Демонстрація відновлення секрету при повторному використанні випадкового числа.
- Збереження результатів раундів у файл журналу.
- Автоматичне тестування реалізації протоколу.

### Вимоги

- Python 3.8 або новішої версії.
- Додаткові сторонні бібліотеки не потрібні.

### Запуск програми

Клонування репозиторію:

```bash
git clone https://github.com/Mario-frog/Information-Law-Labs.git
cd Information-Law-Labs/Lab-05
```

Демонстрація роботи протоколу:

```bash
python ffs_lab5.py demo
```

Моделювання атаки:

```bash
python ffs_lab5.py attack --trials 20000
```

Демонстрація витоку секретного ключа:

```bash
python ffs_lab5.py leak
```

Запуск автоматичних тестів:

```bash
python test_ffs.py
```

### Результати роботи

У результаті виконання програми демонструється успішна автентифікація чесного учасника, відхилення учасника з неправильними секретними даними та аналіз стійкості протоколу до атак.

Результати демонстраційних раундів автентифікації автоматично зберігаються у файлі `ffs_rounds.log`.

### Висновок

У ході лабораторної роботи реалізовано протокол автентифікації Фейге — Фіата — Шаміра. Досліджено механізм підтвердження знання секретного ключа без його передачі іншому учаснику, перевірено працездатність протоколу та проаналізовано його стійкість до атак.
